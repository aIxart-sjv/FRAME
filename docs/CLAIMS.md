# Evidence-backed claims and non-claims

The authoritative statement of what FRAME can be said to do, what has been measured, and what has **not** been demonstrated, as of Phase 8. It carries the Phase 5–7 results forward **unchanged in meaning**, including
the negative and mixed ones: they are part of the evidence, not something to present around. Where this page and an older document disagree, this page is current (see §5 for the older statements it supersedes).

Three kinds of statement are kept apart on purpose: **engineering capability** (the code does this, and a test or a smoke record shows it), **measured evidence** (a run on real data produced these numbers, with these limits), and **not demonstrated** (nothing here supports it).
"Status" values: *implemented and tested*, *measured, limited*, *not demonstrated*.

Sources are named by file. Real-data numbers come from `EVALUATION.md` (Phase 5), `RELIABILITY.md` (Phase 6) and `DOWNSTREAM.md` (Phase 7); all are over **scene units** (a NEON acquisition or a source orthophoto), never over pooled pixels, with no ranking of systems.

## 1. Supported by implementation and testing (engineering capability)

| Claim / capability | Evidence | Status | Caveat |
|---|---|---|---|
| **Rectangular 4× SR inference.** A GeoTIFF of any height and width (not only 128 × 128, not only square) is cut into overlapping 128 × 128 tiles (overlap 32, reflect padding, linear blending), passed through the selected model, and rebuilt into an exactly 4× raster | `frame/tests/test_tiling_*`, `test_api_tiling.py`, the real-model `test_api_tiling_mamba_integration.py` / `test_tiling_mamba_integration.py`; Phase 8 `test_integration_contract.py`; smoke records for toy, Lite and Mamba (200 × 300 → 800 × 1200) | implemented and tested | scenes above 1,048,576 input pixels are refused (HTTP 413; a memory guard, not a scientific limit); the API is synchronous; one model call per tile per ensemble pass |
| **Lite / Mamba model selection with no silent substitution.** `model` is `lite` (default) or `mamba`; unknown ids → 422; an unavailable model → 503; a worker that dies mid-scene → an error and no job. Lite is never run in place of Mamba (or vice versa); the result and the GeoTIFF tag name the model that ran | `test_api_model_selection.py`, `test_api_model_service*.py`, `test_integration_contract.py` (counts the calls of the other model: none), real `test_api_mamba_integration.py`; smoke records | implemented and tested | Mamba needs a CUDA GPU and its own environment (CPU is refused); `GET /health` lists Lite as selectable without checking the weights cache, which is fetched on first use (a failed fetch is a clean 503) |
| **Geospatial consistency of the output grid.** CRS, origin and footprint are preserved; the pixel size goes from 10 m to 2.5 m; height and width are exactly 4×; the stability raster is on the same grid; no seam is added at tile joins for a tile-consistent model | `test_geospatial_*`, `test_tiling_geospatial.py`, `test_integration_contract.py` (GeoTIFF read back from disk), `frame.smoke` checks on real Lite and Mamba output; Phase 6 scene check (both real models) | implemented and tested | this is a statement about the **grid**. It says nothing about the radiometric or geometric accuracy of the *content* |
| **Input validation with named errors.** Not a GeoTIFF, a missing CRS, a wrong or missing band set, no valid pixel (all nodata or non-finite), and a declared scale the values contradict (reflectance called raw DN, or the reverse) are refused at upload with HTTP 400 and a JSON body; NaN/Inf pixels are excluded from the reported valid coverage; every error body is JSON without a traceback or a server path | `test_integration_contract.py`, `test_pipeline.py`, `test_masks.py`, `test_geospatial_geotiff.py`, `test_api_model_service.py` | implemented and tested (Phase 8) | the scale of a scene is never *guessed*: only impossible combinations are refused. The −1000 BOA offset of processing baseline ≥ 04.00 is still **not** applied |
| **Paired-data pipeline.** Adapters, JSONL manifests with content digests, roles, scene/region splits, aligned patch extraction, a seeded recorded degradation chain, QC, a DataLoader | `test_data_*.py` (the SEN2NEON and OpenSR readers ran on real files) | implemented and tested | SEN2NAIPv2 was verified on a 130-pair real sample only, SEN2VENµS is format-only, the India holdout has no data ([`REGISTRY.md`](REGISTRY.md) §2) |
| **Geographic split and leakage controls.** Benchmarks (SEN2NEON, OpenSR-Test, India) cannot enter `train`/`val`; a leakage gate sits in front of every training run; evaluation refuses train/eval overlap | `test_data_splits.py`, `test_data_qc.py`, `test_train_data.py`, `test_evaluate_datasets.py`; mutation-checked in Phase 4 | implemented and tested | exercised on synthetic data and a 100-pair SEN2NAIPv2 sample; no real training set was ever split for training |
| **Training and checkpoint infrastructure.** Strict config, losses, AdamW and schedules, AMP with fallback, gradient accumulation, resumable weights-only checkpoints that record the manifest digest, deterministic validation | `test_train_*.py` (249 tests); `docs/TRAINING.md`; the tiny-CNN and Mamba smoke experiments | implemented and tested | **no real-data training was run.** The smoke runs prove the loop and the resource boundary, not performance ([`TRAINING.md`](TRAINING.md) §9, §12) |
| **Evaluation metrics and aggregation.** A strict valid-pixel rule, PSNR/SSIM/RMSE/MAE/SAM/ERGAS, band and index errors, detail metrics, element-wise added-detail categories, self-consistency kept apart from reference accuracy, aggregation over scene units with bootstrap intervals, provenance per result | `test_evaluate_*.py`; `frame.evaluate` CLI | implemented and tested | a reference is a different sensor with its own registration error; the numbers are comparisons with that reference, not errors against ground truth |
| **Registration eligibility gate** (`frame-reliability-gate/1`). A tile enters a pixel-level analysis only if its reference is registered to the prediction grid; excluded tiles carry a reason and no numbers; the **same** gate serves the reliability and the downstream layers | `test_reliability_eligibility.py`; `test_downstream_runner.py` (an ineligible reference cannot enter: no NDVI, no region, no model call, nothing cached); `test_integration_contract.py` (both layers exclude the same tiles for the same reasons) | implemented and tested | the registration is judged from the bicubic baseline, not from ground truth; it removed 60 % of SEN2NEON tiles, so it also removes evidence |
| **Downstream NDVI analysis machinery.** NDVI on reflectance, fixed 10 m / 40 m regions, a fixed predeclared vegetation threshold (0.3; 0.2 / 0.4 as sensitivity), decision agreement, stability-versus-error association with a texture control, risk-coverage | `test_downstream_*.py` (138 tests, mutation-checked); `frame.downstream {check,run,smoke}` | implemented and tested | the **result** is mixed to null (§2). A land-cover task was not run |
| **Reproducible experiment metadata.** Config digests, seeds, git revision with a dirty flag, weight hashes, manifests, environment capture, per-tile records | every run record under `experiments/`; `frame.smoke` records | implemented | historical runs were made from a **dirty working tree** and say so; GPU bit-identity was verified on this machine only (a repeat of the same seed and scene was bit-identical for the toy model, real Lite and real Mamba); the model artifacts are not revision-pinned |
| **Honest terminology, enforced structurally.** The output is an "SR-derived product — 2.5 m pixel grid"; the stability is a "TTA stability — reconstruction-variation diagnostic"; the NDVI view says it is a demonstration | `test_api_terminology.py`, `frontend/src/__tests__/terminology.test.tsx`, `test_integration_contract.py` | implemented and tested | wording is guarded by tests; presenting the tool is still a human act ([`DEMO_RUNBOOK.md`](DEMO_RUNBOOK.md) §7) |

## 2. Measured, but not universally established

Each row is a real-data result with its limits. None is a statement about how FRAME behaves elsewhere.

| Claim / capability | Evidence (real data) | Status | Caveat |
|---|---|---|---|
| **Model behaviour on SEN2NEON.** Against this reference, both networks differ from bicubic on the pixel-wise and spectral metrics: PSNR, system − bicubic, Lite −0.46 dB [−0.59, −0.34], Mamba −0.46 dB [−0.64, −0.31] (28 units); SAM +0.16° / +0.07°; detail correlation 0.40–0.46 against 0.53 for bicubic | `EVALUATION.md` §8.4 | measured, limited | the reference is AVIRIS-NG-derived, not registered to the Sentinel-2 grid (median displacement of the bicubic baseline 1.0 HR px, max 6.5); removing the estimated shift lifts every system by ≈ 0.15 dB and **does not change the ordering**; what explains the gap could not be separated (sensor radiometry, texture and shadow, land-cover mix) |
| **Model behaviour on OpenSR-Test.** Close to bicubic on the pixel metrics (PSNR difference ≤ 0.11 dB on `spot`, ≤ 0.02 on `spain_crops`, ≤ 0.04 on `spain_urban`); on `spot`, where registration is best, detail correlation higher than bicubic (+0.045 [0.033, 0.058] Lite, +0.048 [0.037, 0.061] Mamba; 9 units) with slightly worse SAM (+0.23° / +0.17°) | `EVALUATION.md` §8.4 | measured, limited | `spain_crops` (5 units) and `spain_urban` (4) are descriptive; the harmonised `HRharm` reference only; Spain and SPOT only |
| **Spectral and spatial metrics.** NIR carries the largest error (B08 RMSE 0.038–0.043 on SEN2NEON), so NDVI error follows (MAE 0.054–0.072 per pixel); the constrained systems reduce back to the input within 0.0012–0.0019 MAE; tile seams add no measurable error (seam / interior 0.99) | `EVALUATION.md` §8.4 | measured, limited | self-consistency is agreement with the model's own input, **not accuracy**; the hard-constraint ablation exists for Lite only (without it PSNR is 1.10 dB [0.93, 1.29] lower) |
| **Downstream NDVI behaviour.** Region-level NDVI MAE 0.02–0.05 for every system including the LR input; differences from bicubic about 0.001 NDVI and ≤ 0.8 percentage points of pixel decisions (threshold 0.3), with a sign that depends on the dataset (a little more disagreement than bicubic on SEN2NEON and `spot`, a little less on `spain_crops`); indistinguishable at 40 m | `DOWNSTREAM.md` §8.2 | measured, **mixed to null** | 11 / 6 / 5 / 4 registration-eligible scene units; the reference is a different sensor, so most of the error is a floor no system removes; no multiplicity correction |
| **Stability–error association.** Within tiles the stability correlates weakly with reconstruction error (Spearman 0.08–0.16 pixel → 10 m on SEN2NEON; 0.17–0.59 on OpenSR); texture and added-detail baselines reach similar values; the partial correlation given both is small | `RELIABILITY.md` §6.2 | measured, limited | not distinguishable from zero across SEN2NEON tiles (0.43 [−0.08, 0.83]); association *rises* when the reference is displaced, which is why the gate exists |
| **Stability–downstream-error association.** Stability-only correlation 0.04–0.22 with the region NDVI error, texture alone 0.03–0.15, partial given texture 0.01–0.17, given texture and added detail −0.02 to 0.10; dropping the 20 % most unstable regions removes ≈ 5–8 % of the mean NDVI error (texture order 4–6 %, an oracle 35–41 %) | `DOWNSTREAM.md` §8.3–8.4 | measured, limited (a small, dataset- and model-dependent residual signal at most) | about twenty intervals from 4–11 units, none corrected for multiplicity; an ordering, **not calibrated selective prediction** |
| **Cost.** Mamba costs about two orders of magnitude more than Lite per tile (§3 of [`REGISTRY.md`](REGISTRY.md)) | Phases 1, 2, 6, 8 timing records | measured on one machine | says nothing about quality; not a production throughput figure |

## 3. Explicitly NOT demonstrated

These are not "pending polish": the evidence gathered either contradicts the claim or does not reach it.

| Not demonstrated | Why (what was found, or not done) |
|---|---|
| **Calibrated uncertainty** | The raw TTA spread is 16–32× smaller than the actual error and a ±2σ band covers 5–8 %; no calibration was assessed (a development/test protocol needs ≥ 12 units, ≤ 11 existed). The stability is an uncalibrated diagnostic |
| **Superior high-error detection from the TTA stability** | Descriptive only: AUROC 0.46–0.48 on SEN2NEON (chance); 0.82–0.89 on OpenSR-Test against 0.79–0.87 for the texture baseline. Not shown to beat a trivial predictor |
| **A consistent downstream advantage over bicubic** | Phase 7: mixed to null, dataset-dependent sign, differences far below the cross-sensor error floor |
| **Universal geographic generalisation** | Evidence is North America (SEN2NEON) and Spain / SPOT (OpenSR-Test) only; no domain-shift or temporal experiment was run |
| **Indian downstream validity** | `india_downstream_validation_unavailable`: no Indian HR reference and no Indian label in this repository; no synthetic Indian truth was made |
| **Region-level land-cover classification** | `secondary_landcover_task_deferred_no_supported_reference`: the only label is one NEON superclass per whole tile; the thresholded NDVI decision is a vegetation proxy, not a classifier |
| **Production-scale throughput** | The API is synchronous, in-memory and single-process; a 1024 × 1024 Mamba request is ≈ 20 min by arithmetic; no load test, queue, auth or deployment |
| **A universally optimal SR model** | No ranking was made or is supported; differences are small, sign-changing and dataset-dependent |
| That the output is **native 2.5 m Sentinel-2** or has been **validated as accurate at 2.5 m** | Sentinel-2 never observed the ground at 2.5 m; no 2.5 m ground truth exists for any Sentinel-2 scene |
| That Mamba **outperforms** Lite, or the reverse | Not shown; differences are within scene-to-scene spread and change sign |
| **Real-data training or fine-tuning results** | No training on SEN2NAIPv2 / SEN2VENµS was run; the smoke experiments are synthetic and prove the loop only |
| **Out-of-distribution or domain-shift detection** | Not evaluated |
| **12-band / SWIR / NDBI-type products** | RGBN ×4 only; the 10-band cascade and LDSR-S2 are not integrated |
| That low stability means hallucination or high stability means accuracy | The requirements' own warning ("stable ≠ correct; uncertain ≠ wrong"); the measured association is weak |

## 4. Wording for a presentation

Following the tiers of `Requirements 142.txt` (§11.31 and §12.34 there): use the first column; do not use the third.

| Safe with the current evidence | Needs evidence FRAME does not have | Do not say |
|---|---|---|
| "FRAME converts Sentinel-2 imagery into GIS-ready super-resolved products through tiled inference, geospatially consistent reconstruction, validation, model-stability analysis and downstream analytical processing." | "…identifies regions requiring additional scrutiny…" (Phase 6 did not show the stability does this reliably) | "FRAME provides uncertainty" / "true uncertainty" / a confidence, a probability of error, a reliability score |
| "The output is an SR-derived product on a 2.5 m pixel grid; Sentinel-2 has not observed the ground at 2.5 m." | "…improves downstream land-cover or change analysis…" (NDVI: mixed to null; land cover: not run) | "true 2.5 m imagery", "recovers the actual sub-pixel scene", "ground truth at 2.5 m" |
| "FRAME reports a TTA stability diagnostic and tests it against error; in the evidence gathered the association is weak and about as strong as image texture." | "…works across geographies / on Indian terrain…" | "works anywhere", "globally generalisable", "sensor-independent" |
| "FRAME measures SR against independent references with a registration gate, per scene unit, with intervals, and reports differences from bicubic that are small and dataset-dependent." | "…the best / a better model…" | "best", "winner", "superior", "state-of-the-art", any model ranking |
| "The NDVI view is a demonstration on one scene; reference-based tests found small, mixed differences." | "…real-time / production-scale processing…" | "real-time", "production-ready" |

## 5. Older statements this page supersedes

* `FINAL_SCIENTIFIC_AUDIT.md` (Phase 9 of the original build, Lite-only, 128 × 128, one scene plus nine `spot` samples) said the frozen model is "marginally better than bicubic on most metrics" and that the uncertainty "is not noise". Both were read on 9 unregistered samples and one scene. **Phase 5 (28 SEN2NEON units, 57 OpenSR scenes) and Phase 6 supersede them** (§2, §3). The audit remains the record of what that stage established; its own list of things not to claim (its §H) still holds and is extended here.
* `experiments/validation/README.md` states that the model "outperforms bicubic" on four of five metrics on 9 samples. That is a historical record made before the registration analysis; it is kept unmodified, with a pointer to this page at its top.
